## Design Context

### Users
macOS developers who use Grok Build for sustained coding work across several local projects and concurrent agent sessions. They need dense status information without losing focus or granting accidental machine access.

### Use Cases
- Add a local project and keep several resumable Grok sessions attached to it.
- Read streaming answers, reasoning summaries, tool activity, plans, questions, and permission prompts.
- Switch model, reasoning effort, and operating mode without leaving the session.
- Inspect context usage, MCP activity, tasks, workflows, updates, and recoverable failures.

### Brand Personality
Native, focused, exact, and operationally trustworthy. The app should feel like a serious macOS developer instrument: quiet while idle, explicit when an agent is acting, and never visually confused with a generic web dashboard.

### Aesthetic Direction
Refined industrial macOS. Use cool mineral surfaces, ink-like text, small cobalt status accents, precise separators, and restrained motion. Preserve the original GrokBuild information hierarchy while improving optical sizing and legibility. Avoid neon AI styling, gradient text, glass-card stacks, oversized controls, and ornamental dashboards.

### Design Principles
1. The transcript is the primary surface; chrome remains compact.
2. Tool execution and permission state must always be visible and attributable.
3. Density comes from hierarchy and alignment, not tiny text.
4. Every privileged operation crosses an explicit main-process boundary.
5. Light/dark appearance, reduced motion, keyboard navigation, and screen-reader labels are first-class.
6. Visual parity is measured against reference screenshots, not intuition.
